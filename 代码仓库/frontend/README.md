# 软装改造 · 正式前端

阶段 3：已接通**真实生成闭环**。用户上传房间照片 → 选风格 → 按房间/家具选具体款式 → 确认费用后调用后端生成 → 跳转结果页查看同角度效果图与选购链接。

## 页面入口

- `/` 是宣传首页：保留原主视觉，依次展示五种设计风格、可拖动的前后对比，以及客厅、卧室、餐厅展示案例。
- `/design` 是功能页：左侧集中上传照片、选择风格、房间、家具与具体款式；右侧固定承载原图预览、生成后的前后拖动对比和商品对应链接。
- 顶部导航提供“首页”“开始设计”和“登录”按钮；当前没有账号系统，“登录”只作为未启用入口，不会伪造登录功能。
- 首页的前后对比与三类案例均明确标为展示案例，不使用或暗示任何用户上传照片、历史生成结果。

- 生成走后端**异步任务**：前端提交后轮询任务状态，完成后直接在 `/design` 右侧展示结果、前后对比和商品链接；独立 `/r/{taskId}` 仍作为刷新恢复入口。生成可能需要数分钟，页面显示等待说明（不显示虚假百分比）。
- 结果页展示效果图、本次成本与图内元素的选购链接（当前为静态淘宝搜索链接，无佣金）。
- 24 类家具各 3 个图片选项为明确标注的 AI 款式示意，不是真实在售商品；具体款式 ID 会传给后端，由后端读取同一目录并裁出选中图片作为模型参考。参考图链路已接通，真实款式还原效果待验，不保证精确复刻。

## 本地启动

### 临时微信演示（方案 A）

在前端目录运行 `npm run build:demo`，再运行 `npm run serve:demo`，得到 `http://127.0.0.1:3101/`。通过免费 Cloudflare Quick Tunnel 仅分享此 3101 静态服务，不能分享 3000/8000 业务服务。

`cloudflared tunnel --url http://127.0.0.1:3101 --protocol http2 --no-autoupdate`

终端返回的 HTTPS 地址可转发。电脑须保持开机联网、静态服务和 tunnel 均运行；重启 tunnel 会换地址。这是临时演示，微信内及国内不同网络的可达性需要真机验证。

09-21 当前网络无法连接 Cloudflare 隧道节点，已使用 Pinggy SSH 临时通道代替（`ssh -p 443 -R0:127.0.0.1:3101 free.pinggy.io`，可使用专用临时 SSH 密钥）。每次免费会话约 60 分钟，首访须点 `Enter site`；续开会换地址。当前地址及过期时间见 `docs/项目状态.md`。分享期间只需运行静态服务，无需启动后端。演示 PNG 有单独 WebP 传输副本，原素材不覆盖。

演示包含首页、5 种风格、24 类家具筛选、固定前后对比示例及淘宝相似款搜索。选款不改变示例图，不上传原图、不产生模型费用，刷新后清空草稿。公开服务只提供 `.demo-build` 静态产物，禁止写请求、API、历史结果和隐藏文件；构建使用源码白名单，不读取 `.env` 或后端数据。本机正常开发和真实生成功能不变。

### 完整本机体验

需要 Node.js 22.12+ 与 npm，以及运行在 `127.0.0.1:8000` 的现有 FastAPI 后端。

在 `代码仓库/backend/` 启动后端（已配置过的环境无需重复安装或复制配置）：

```sh
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

在 `代码仓库/frontend/` 执行：

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:3000/ 。前端通过同源 `/api/v1/*` 转发到后端。若使用其他后端端口，可在前端 `.env.local` 设置 `BACKEND_URL` 并重启。只填写服务地址，不在前端填写模型 Key。

日常修改和本机预览保持使用 `npm run dev`。本项目 Next.js 的开发输出在 `.next/dev`，生产构建在 `.next`，可以在开发服务运行时做构建检查。

生产模式本地验证（先停止占用 3000 端口的前端服务）：

```sh
npm run build
npm run start
```

不要在 `npm run start` 正运行时再次执行 `npm run build`：旧服务可能继续返回旧 HTML，而新构建已替换对应脚本，造成首页能开、按钮和图片目录失效。生产模式重新构建时必须先停止旧前端，再构建、再启动，最后执行 `npm run check:assets`。后端无需一起重启。

`rewrites` 的目标地址在构建时确定，修改 `BACKEND_URL` 后必须重新构建。`standalone` 产物的资源拷贝与云端部署在上线阶段处理。

## 数据与隐私

- 选择照片只生成本地预览；点击“上传这张照片”后才发送至本机后端。
- 后端对上传做真实类型与大小验证，前端的限制仅用于提前提示。
- 确认生成后，照片与已选款式参考图经本机后端发送至确认页显示的国内图像服务（当前为火山方舟）用于出图；照片不在前端持久化，后端出图后即从内存删除。
- 照片不放入 Local Storage、URL、日志或前端目录。本地预览 URL 在替换/卸载时释放。
- 风格与元素为后端目录；图片款式来自本地 `furniture-catalog.json` 示意图库。未提交的草稿刷新后需重新选择；已提交任务的选款 ID、名称、图片路径与面板编号由后端持久保存。
- 生成任务的结果图与状态由后端保存，结果页可通过 URL `/r/{taskId}` 恢复查看。
- 生成协议新增 `furniture_selections: [{element_id, option_id}]`，后端校验一一对应，不接受客户端任意图片 URL。Ark 逐张传入 1 张房间原图及最多 13 张商品图，不合并参考板；旧供应商维持 1–2 件单图、多件两张参考板。只请求一次生成。结果页展示本次参考款式；这不等于已验证模型精确复现，需逐件核对。
- 当前无登录，只适用于本机体验，启动默认仅绑定 `127.0.0.1`。
