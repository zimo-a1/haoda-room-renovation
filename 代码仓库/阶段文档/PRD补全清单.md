## 必须问（本轮 5 个，每个附推荐）

### 问题 1：第一版（MVP）做多大范围？
- 为什么重要：决定第一阶段交付范围和工作量。
- 选项：A) 只做 F1–F5（上传→出图→跳淘宝购买），转化追踪 F6 后做；B) F1–F6 全做（一开始就做精细化转化上报）
- 推荐：**A**。核心闭环先跑通，购买转化率先用淘宝客后台的 PID 报表看，F6 精细化上报第二阶段补。
- 不选的后果：选 B 第一阶段工作量变大，拖慢出图闭环的验证。

### 问题 2：出图是同步等，还是异步生成后通知？
- 为什么重要：决定交互方式和后端架构（是否要任务队列/轮询）。
- 选项：A) 同步等待（页面一直等出图，带进度提示）；B) 异步（提交后离开，出图后回来查看）；C) 等待页 + 超时转异步
- 推荐：**A**（MVP 最简）。若实测出图超 60 秒，再转 C。
- 不选的后果：选 B 要额外做任务状态持久化和轮询，MVP 阶段多一套机制。

### 问题 3：单次出图成本上限设多少？（每月模型预算）
- 为什么重要：PRD 安全规则「成本上限未配置时拒绝出图」——没数字就出不了图。
- 选项：A) 单次 ¥2 + 每月 ¥300；B) 只设每月总预算 ¥300；C) 你给个具体数字
- 推荐：**A**。图像编辑单次通常几毛到一两元，¥2 能覆盖主流模型，超了拒绝；每月 ¥300 防失控。
- 不选的后果：不设则出图被安全规则自动拒绝；设太高成本可能失控。

### 问题 4：谁来用、怎么登录？
- 为什么重要：决定登录方式、数据隔离和上线形态。
- 选项：A) 邀请码登录，先内部小范围试用；B) 手机号/微信登录，直接对外；C) 先不登录，本地体验
- 推荐：**A**。MVP 先小范围验证转化率，邀请码实现简单，且满足「用户只能看自己数据」。
- 不选的后果：选 B 需实名/备案/客服，上线周期拉长；选 C 无法上线给别人用。

### 问题 5：房间照片可以传给哪些模型？是否允许出境？
- 为什么重要：隐私边界。PRD 说「照片不外传」，但出图又必须把照片发给图像模型，需要把话说清。
- 选项：A) 照片只传给国内图像模型（蚂蚁 MaaS）出图，不传给境外 LLM，不留存；B) 允许传给所有需要的模型（含境外 LLM），只要不留存；C) 完全禁止照片离开本机（会导致无法云端出图）
- 推荐：**A**。既满足出图，又守住隐私；主 LLM 只处理文字（风格/元素），不接触照片。
- 不选的后果：选 B 有出境合规风险；选 C 出图功能做不了（云端模型必须收图）。

## 可默认（已用默认值填上，请确认一次即可）
| 缺口 | 默认值 | 理由 |
| --- | --- | --- |
| 使用频率/并发量 | 低频改造型；MVP 按单进程、并发 5–10 路设计 | 低频场景单进程够用，达规模再上队列 |
| 出图时延 | 单次 2 分钟内可接受，超时重试 | 图像编辑常态范围 |
| 上传图片大小/格式 | ≤10MB，jpg/png/webp | 手册默认文件边界 |
| 效果图留存 | 效果图留存 7 天（本地目录），照片不留存 | 用户要回来点图内商品；照片属隐私不留 |
| 风格库/软装元素库来源 | 先内置静态清单（配置），后接淘宝客选品库 | 先跑通闭环，动态映射是优化项 |
| 图像模型选型 | 配置项 `IMAGE_MODEL_ID`，接 API 时定 | PRD 已明确配置项 |
| 部署位置 | 国内 | 淘宝客 + 蚂蚁 MaaS 均国内 |
| 数据落库 | SQLite 本地文件 | 手册默认，单进程够用 |
