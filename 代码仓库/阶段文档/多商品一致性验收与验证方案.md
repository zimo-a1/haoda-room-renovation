# 多商品一致性：验收标准与下一步验证

日期：2026-09-19。阶段 3 第 2 子阶段。状态：产品验收标准已明确，当前效果未通过；本文不是修复完成报告。

## 产品经理明确的目标

每一件已选商品都必须出现在生成结果中，并对应其具体款式。床品缺失或不相像是核心缺陷，不应把问题缩小为是否默认附带床品，也不能要求用户只选一件来回避多件需求。

| 核对项 | 通过要求 |
| --- | --- |
| 选款覆盖 | 选择 N 件，逐项核对 N 件，漏任意一项不通过 |
| 款式身份 | 不是只核对“有床/有灯”；还需核对轮廓、结构、主色、材质、床品图案等辨识特征 |
| 类目独立 | 床架按床款；床品按单独选中的床品；床头柜、书桌、台灯、主灯、地毯分别对应，不能互相覆盖 |
| 完成定义 | API 出图成功只代表产物可读，不能作为上述项目全通过的证据 |
| 不可见或放不下 | 应说明冲突并请求调整位置/视角，不能悄悄漏掉；不得把该例计为成功 |
| 房间约束 | 在逐件对应基础上保留房间结构、原始视角，不用换一个房间来伪造成功 |

前一轮“选择床默认包含卡片里的床品”的建议没有获得确认，不实施。明确选择了床品时，以床品选项为独立目标。

## 已核对的事实

1. 本机数据库有 16:12 的 7 件提交记录：木质靠背床、复古格纹床品、单抽屉床头柜、蘑菇台灯、木质书桌、枝形吊灯、素色圈绒地毯。任务为 `failed`，并非前端没有提交这些选项。
2. 16:15 的任务仅选择木质靠背床，状态为 `succeeded`，结果与产品经理提供的房间图一致。所选参考图对应图库第 1 款；床架木色和结构细节仍偏离，不能算款式还原通过。
3. 当前实现超过 2 件时会把全部选款压入两张编号板，模型仍只调用一次。代码测试能验证不漏传，不能证明模型不漏画或不串款。
4. 后端只要下载到图片就写入 `succeeded`，没有对生成图逐件定位与比较。任务完成和商品一致性缺少独立验收状态。
5. 多件失败任务没有保存安全错误码或供应商追踪标识，本轮不能仅凭 `failed` 推断它具体是超时、输入限制还是其他上游问题。

当前 SiliconFlow 官方接口为该 2509 模型提供 `image`、`image2`、`image3`。因此现方案把原房间之外的多件商品拼板；这是一种输入组织办法，不是逐件保真机制。参考：[SiliconFlow 图像生成参数](https://docs.siliconflow.cn/docs/api/images-generations-post)。

## 唯一推荐的下一步：先用全选款样例验证候选，不直接替换线上链路

建议新增国内火山方舟的 Seedream 4.5 作候选验证。理由是官方明确提供多图编辑和主体对应能力，适合验证“原房间 + 各件独立商品图”，但官方能力说明并不能证明本项目 7 件商品会一次准确还原。候选的具体输入数量限制、账号可用性在接入前继续核对，超限必须明确阻止，不能重新拼板或截断后声称逐件输入。

- 保留现有 SiliconFlow 与 ModelScope 实现；没有批准前不修改配置、不创建付费资源、不调用新服务。
- 测试使用同一张经用户授权的原始房间照片和全部 7 件选款，不能用结果图冒充原始房间。原照片按现行规则未持久保存，需要重新上传。
- 第一轮最多 4 次单图生成，出图费用合计不超过 ¥1；当前官方公布 Seedream 4.5 为 ¥0.25/张，调用前复核账户价格。没有付费自动重试、不启用多图输出，不用“免费额度可能存在”替代预算控制。
- 初次采用人工逐项对照并记录 7/7 是否出现及是否同款，不冒称已有自动质检。多件一致性未通过前不把候选接为默认，不宣告问题解决。
- 若仍有漏项/错款，再依据实际失败项评估定位、局部修复与自动视觉核验；相关额外费用、是否需要更多商品视角另行说明，不能先堆工作流并承诺必然奏效。
- 即使换模型，也不承诺每次百分之百复现商品细节；产品应将不符合逐件标准的产物认定为待修正，而非以“风格相近”放行。

官方依据：[Seedream 4.5 多图编辑介绍](https://seed.bytedance.com/en/seedream4_5)、[火山方舟官方价格](https://www.volcengine.com/product/ark)。这是一项需确认新增服务与有限测试费用的建议，不是已批准的替换决策。
