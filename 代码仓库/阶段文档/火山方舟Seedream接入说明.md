2026-09-19。范围为阶段 3 第 2 子阶段的生成供应商适配，不改页面视觉、不创建云资源、不做付费测试。

## 已落地

- 按产品经理给出的精确名称 `doubao-seedream-5-0-260128` 接入，未擅自替换为 Lite/Pro/4.5。
- API 为 `https://ark.cn-beijing.volces.com/api/v3/images/generations`，密钥只在后端 `.env`。本地 `IMAGE_PROVIDER=ark`；旧供应商配置保留但不自动回退。
- 前端仍然上传一张房间原图，从图库选择商品。后端裁出每个已选款式的单格图片，按选款顺序组成 `image=[原图, 商品1, …, 商品13]`；每张用 Base64 数据 URL。没有截断、拼板或第三方上传。
- 提示词逐图关联类别和款名，要求每件都出现；分别选择床和床品时，各自决定对应部分，不让床图附带床品覆盖选中的床品。这是输入约束，不是已保证效果。
- 仅生成一张 2K 图，`sequential_image_generation=disabled`、`stream=false`、`response_format=b64_json`；按产品经理最新确认改为 `watermark=false`，关闭后续图内可见角标，页面 AI 效果图说明保留，不处理历史文件。不启用联网搜索。校验单张返回及实际图像后保存 JPEG。
- 按最新确认允许所选家具在原功能分区内小范围摆位，保留具体款式与房间硬装、未选物品、机位；加强类别布置与自然光影要求，三款床头柜增加绑定图集版本和单格的结构约束。仍是一次生成的提示要求，不是自动视觉验收，不能保证每次结果满足全部要求。
- 超时默认 180 秒；付费 POST 自动重试 0 次，不跟随重定向。失败保留固定安全错误码，禁止显示或保存供应商原始报错、请求正文和密钥。
- 元数据存追加表 `task_generation_details`，旧任务表不改；未完成任务在重启后明确标为中断，不重新调用供应商。原图按既定隐私策略不落盘，因此不会宣称重启后能自动续传生成。

## 确认页与接口

`GET /api/v1/generation-options` 返回提供方、显示名称、精确模型、配置就绪、商品数量上限、逐图开关、单次估算及安全提示。配置就绪仅表示本地配置通过，**不表示账号已开通该型号**。前端不拿密钥。

`POST /tasks` 保留已有请求，生成前校验选款、数量、图片格式尺寸、配置及预算。超限返回 400，缺 Key 返回 503，预算不足返回 402；均不消耗原图或创建付费任务。

任务响应新增 `generation_provider / generation_model / input_image_count / error`，向后兼容。失败仍是持久化任务状态，GET 返回固定 `error.code/message`。前端按已知错误码显示提示，失败图不渲染成成功结果。

## 费用与真实验证边界

- 当前 `ARK_ESTIMATED_COST_PER_IMAGE=0.30` 仅沿用已有单次预算作保守估算，不声称是此模型官方单价；输入多张图不在本地预算里按张倍增。账单最终以火山控制台为准。
- 本地接入上限设为 1 张原图 + 13 张商品图。离线测试验证全部 14 张发送，真实 API 对指定型号及账号的上限、权限、收费仍待验证。
- ARK_API_KEY 已由产品经理填写并重启加载，本地配置及前端代理 configured=true；用户已自行生成含 6 / 9 件选款的结果，链路可出图，但发现床头柜结构偏差与美观不足。最新水印/摆位策略未代用户实测。多图不等于逐件匹配，仍按 D2/D3 标准核验，不降低漏项或错款要求。
- 当前选款库为 AI 示意，不是真实在售 SKU；本轮不扩展成批量上传商品图片/商品库管理功能。
