# 技术适配声明

> 阶段 1 产出 · 生成于 2026-09-16

## 1. 产品形态判断
- 产品类型与核心任务：C 端软装改造工具——上传房间照片 → 选风格/元素 → AI 生成「与原图同角度」的软装效果图 → 点击图内商品跳淘宝购买。
- 核心交互：分阶段确认（上传→选风格→选元素→确认出图→点商品）；其中「出图」是计费动作，需用户确认（权限=ask）。
- 开发路径：**后端先行**。核心价值是效果图质量，交互不复杂；MVP 用单文件 HTML 验收页判断效果图质量即可，先跑通后端闭环。
- 当前阶段范围：阶段 2（后端 MVP）= F1–F5 核心闭环 + 最小验收界面；F6 转化追踪、登录、正式前端后置。

## 2. 采用的默认方案
| 方案 | 采用原因 |
| --- | --- |
| Python 3.12 + FastAPI + Pydantic + pytest | 手册默认后端栈，单进程服务一条命令启动，符合 PRD 非功能要求 |
| Git 管理 + `.gitignore` + `.env` 外置密钥 | 强制底线（密钥不进仓库、不进前端） |
| 模型调用走官方 SDK / 兼容接口 | 图像走蚂蚁 MaaS 图像编辑 API（配置项 `IMAGE_MODEL_ID`）；LLM 走 Anthropic 兼容网关（配置项 `MODEL_ID`） |
| SQLite + SQLAlchemy | MVP 单用户低频，需持久化任务与商品映射（出图记录、跳转链接），重启不丢 |
| 单文件 HTML 最小验收界面（挂后端 `static/`） | 效果图需「用眼睛看」判断质量，但 MVP 不引入前端脚手架 |

## 3. 触发的按需模块
| 模块 | 由哪条需求触发 | 当前阶段是否引入 |
| --- | --- | --- |
| SQLite + SQLAlchemy | 任务状态持久化、商品映射 | ✅ 引入（SQLite 本地文件） |
| 本地文件目录 | 效果图等大文件存储 | ✅ 引入（效果图存本地，7 天） |
| 任务队列 | 长耗时任务、并发 | ❌ 暂缓（MVP 同步等待，单进程） |

| RAG / Chroma、python-docx、pypdf、OCR | 未触发 | ❌ 不引入 |
| Alembic 迁移 | schema 演进 | ❌ 暂缓（MVP schema 简单） |
| 对象存储 | 生产文件存储 | ❌ 暂缓（本地目录够用） |

## 4. 偏离或暂缓的默认方案
| 默认方案 | 替代方案 | 原因 | 影响 | 何时重新评估 |
| --- | --- | --- | --- | --- |
| 正式前端（Next.js+TS+Tailwind） | 单文件 HTML 验收页 | MVP 先验证出图闭环 | 无正式视觉 | 阶段 3 上正式前端 |
| 登录与数据隔离 | 先不登录（本地单机） | PM 决策 4C | 多用户数据隔离后置 | 上线（阶段 4）前必加邀请码登录 |
| 异步任务队列 | 同步等待出图 | PM 决策 2A，MVP 最简 | 出图超时风险 | 实测出图超 60 秒或出现并发时 |
| 转化追踪 F6 | 先用淘宝客 PID 报表看转化 | PM 决策 1A | 无精细化归因 | 阶段 2 后续子阶段 |

## 5. 强制底线检查
- 密钥与隐私：**通过**（`.env` 外置 + `.gitignore`；照片只传国内图像模型，不留存不落库）
- 数据与任务可恢复：**通过**（SQLite 持久化任务与商品映射，重启不丢）
- 输入输出校验：**通过**（Pydantic 校验接口与模型结构化输出；上传图片校验格式/真实类型/大小 ≤10MB）
- 错误与日志边界：**通过**（错误统一 `{"error":{"code","message"}}` 不泄露堆栈；日志不记密钥/密码/完整照片）
- 测试与真实模型验收：mock 自动化测试（pytest）每阶段必跑；真实模型冒烟（图像出图 + 淘宝客链接）验收前必做，无 Key 时如实记「待验」
