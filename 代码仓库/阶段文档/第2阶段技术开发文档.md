# 第 2 阶段技术开发文档｜后端 MVP

> 配套文档：软装改造应用-PRD、通用技术栈手册、技术适配声明、PRD 补全清单
> 本文档只覆盖第 2 阶段（F1–F5 核心闭环），不提前实现登录、F6 转化追踪、正式前端、异步队列。

## 一、阶段目标
- 交付范围：F1 照片上传、F2 风格筛选、F3 软装元素挑选、F4 同角度效果图生成、F5 商品点击购买（跳淘宝）。
- 阶段产物：可运行的后端服务（一条命令启动）+ 最小验收网页 + mock 测试通过 + 证据包。
- 验收标准（对齐 PRD）：
  1. 上传一张房间照片 → 选风格 → 选元素 → 生成一张同角度效果图 → 查看图内商品跳转（淘宝客未配置时明示「暂无对应商品」）。
  2. 照片不落库、不留存；单次出图成本 ≤ ¥0.5；未配置成本上限时拒绝出图。
- 明确不做：登录/数据隔离、F6 转化追踪、正式前端（Next.js）、异步任务队列、LLM `/chat` 入口。
- 本阶段打通的主链路：上传 → 选风格 → 选元素 → 真实出图 → 静态商品链接跳转淘宝搜索（完整走通）。

## 二、技术适配摘要
- 引用《技术适配声明》结论；开发路径：后端先行。
- 采用：Python 3.12 + FastAPI + Pydantic + pytest + SQLite/SQLAlchemy + 单文件 HTML 验收页。
- 启用按需模块：SQLite + SQLAlchemy（任务/商品映射持久化）、本地文件目录（效果图）。
- 偏离/暂缓：登录、F6、正式前端、任务队列、SSE、Alembic、对象存储（理由见技术适配声明）。

## 三、技术栈与模型
- 实际用到的组件：FastAPI、Uvicorn、Pydantic、pydantic-settings、SQLAlchemy、Pillow（图片校验/水印）、python-multipart（上传）、httpx（测试客户端）。
- 模型：F1–F5 不触发 LLM；仅触发图像编辑模型（SiliconFlow `Qwen/Qwen-Image-Edit-2509`，图生图，配置项 `IMAGE_MODEL_ID`）。`IMAGE_MODEL_ID=mock` 时返回带「MOCK」水印占位图（不得当作真实模型结果）。
- 淘宝客：选品库 API + 推广链接 API（配置项），未配置时明示「暂无对应商品」，禁止编造。

## 四、环境与配置
- 配置项见 `backend/.env.example`（不含密钥）。
- 需要用户提供：图像模型 Key；商品购买当前采用静态淘宝搜索链接，不依赖淘宝客 Key。
- 启动端口：8000；一条命令启动（见 README）。

## 六、数据、资产与状态
- 持久化：SQLite（`generation_tasks` 表），字段：id、style_id、element_ids(JSON)、status、result_image_path、cost、created_at、updated_at。
- 照片：**不落库、不留存**，仅在内存 `photo_store` 暂存，出图完成后立即删除；进程重启后照片丢失（符合 PRD，用户重传即可）。
- 效果图：本地目录 `data/results/`，留存 7 天（MVP 记录规则、不做自动清理）。
- 状态机：任务 `status ∈ {processing, succeeded, failed}`；MVP 同步出图，仅 `succeeded`/`failed` 落地。

## 七、API / 工具设计
所有错误统一返回 `{"error": {"code", "message"}}`，不泄露堆栈。同步出图（PM 决策 2A），无 SSE。

| 方法 | 路径 | 说明 | 主要错误码 |
| --- | --- | --- | --- |
| POST | `/api/v1/photos` | 上传照片（校验格式/真实类型/大小/文件名） | INVALID_IMAGE |
| GET | `/api/v1/styles` | 风格列表 | — |
| GET | `/api/v1/styles/{id}/elements` | 某风格的元素列表 | STYLE_NOT_FOUND |
| POST | `/api/v1/tasks` | 出图（选风格+元素），同步返回结果 | PHOTO_NOT_FOUND / STYLE_NOT_FOUND / INVALID_ELEMENTS / COST_LIMIT / IMAGE_GEN_FAILED |
| GET | `/api/v1/tasks/{id}` | 查任务与结果 | TASK_NOT_FOUND |
| GET | `/api/v1/tasks/{id}/image` | 获取效果图 | IMAGE_NOT_FOUND |
| POST | `/api/v1/tasks/{id}/products` | 查图内元素对应淘宝商品/链接 | TASK_NOT_FOUND |

## 八、Prompt 设计
- 本阶段无 LLM Prompt（F1–F5 不触发 LLM）。图像模型的入参（风格/元素）为结构化参数，非自然语言 Prompt。

## 九、验收界面
- 单个 HTML（`backend/app/static/index.html`），临时验收工具（非正式前端）。
- 功能：上传 → 选风格 → 选元素 → 生成 → 看图 → 查商品。

## 十、测试要求
- 第一层 mock 测试（pytest，模型调用全部 mock，离线可跑）：上传校验、风格/元素目录、出图主链路、成本上限、商品查询、统一错误结构。
- 第二层真实冒烟：SiliconFlow 图像模型真实出图；商品购买验证静态淘宝搜索链接。淘宝联盟选品与佣金能力不在本阶段。

## 十一、验收清单（产品经理照着点）
- [ ] 启动服务，打开验收页
- [ ] 上传一张房间照片，页面显示「上传成功」
- [ ] 选一个风格，能看到该风格的软装元素列表
- [ ] 勾选若干元素，点「生成」，能看到一张带 MOCK 水印的效果图
- [ ] 点「查看商品」，页面显示所选元素及「暂无对应商品」提示（未配置淘宝客时）
- [ ] 重启服务后再查任务，任务记录仍在（数据可恢复）

## 十二、风险与待确认项

- 商品购买：当前静态链接（无佣金），接联盟 Key 后升级。
- 需产品经理决定的问题：无（阻塞项）。
