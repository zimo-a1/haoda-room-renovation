## 1. 本阶段目标

用户打开正式网页后，可以上传自己的房间照片、看懂当前步骤、选择喜欢的风格和软装元素，并在明确知道会产生约 ¥0.30 成本后确认生成；本子阶段先交付这条流程的代表页和工程骨架供视觉确认。

## 2. 范围

### 本阶段包含

- 页面：`/` 工作台代表页。
- 布局：全幅室内摄影、编辑手记、横向风格目录、桌面双栏工作台、移动端单列、正常文档流内的主要操作区。
- 组件：页面顶栏、步骤导航、照片上传器、图片预览、风格卡、房间/家具分类、具体款式图片单选、带缩略图的搭配清单、费用确认层、统一按钮/提示/骨架屏。

## 3. 用户流程

1. 打开页面，看到暖光室内主视觉、产品价值与风格索引；意向图明确标注 AI 创作。
2. 在工作台最上方选择 jpg/png/webp 房间照片，先本地预览；明确点击“上传这张照片”后提交。前端检查 10MB 上限，后端继续校验真实类型、安全文件名和大小。
3. 下方横向浏览并选择一种风格，中古风排在最前但不预选；前端从真实接口加载元素。
4. 风格下方先点客厅、卧室或餐厅，再点家具分类（例如床）。分类下面显示 3 张不同造型的 AI 示意款式图，不默认选中款式。
5. 点击图片加入清单；每类限一款，再选即替换。跨房间保留选择，清单可移除。照片上传成功、选好风格且至少选好一款后，激活“预览生成信息”。
6. 打开费用确认层，看到已选风格、家具、具体款名和缩略图、预计成本及隐私说明；明确图片不是在售商品、尚未接入生成，本次不调用模型、不产生费用。
7. 本子阶段到此为代表页验收终点；产品经理确认视觉后，下一子阶段接通真实生成与结果页。

## 5. 接口契约

### `GET /api/v1/styles`

- 成功：`{ "styles": [{ "id": string, "name": string }] }`。
- 失败：统一转换为前端 `AppError`，展示“风格加载失败，可重试”。
- 超时：10 秒；只对 GET 做一次用户触发的重试，不做后台无限重试。

### `GET /api/v1/styles/{styleId}/elements`

- 成功：`{ "style_id": string, "elements": [{ "id": string, "name": string, "room": string }] }`。
- 主要错误：`STYLE_NOT_FOUND`。
- 风格快速切换时取消上一次请求，避免旧响应覆盖新选择。

### `POST /api/v1/photos`

- 请求：`multipart/form-data`，字段名 `file`。
- 成功：`{ "photo_id": string }`。
- 主要错误：`INVALID_IMAGE`、`VALIDATION_ERROR`。
- 超时：30 秒；超时后不自动重复上传，由用户点击重试。

### 统一错误

- 后端：`{ "error": { "code": string, "message": string } }`。
- 前端：转换成 `{ code, message, userMessage, retryable }`；界面只展示普通用户可理解的 `userMessage`，不展示堆栈或供应商信息。

## 6. 实现方案

- 路由：App Router 的 `/`。
- 组件结构：页面只负责编排；上传、风格、元素、确认层分别放进 `features/renovation/components/`。
- 状态来源：风格/元素和上传结果以后端为准；图片款式由本地 `furniture-catalog.json` 定义（按元素 ID 映射 3 款）。`Record<elementId, optionId>` 存偏好，清单只接受属于当前元素的有效款式；文件预览和选择是页面临时草稿状态，不等同于持久任务。
- 接口代理：浏览器只访问同源 `/api/v1/*`；Next.js 用服务端 `BACKEND_URL` 代理到 FastAPI。
- 响应式：内容最大宽度 1200px；桌面保留 120px 侧栏标签与双栏工作台；900px 以下标签转到内容上方；680px 以下工作台单列；风格目录独立横向滚动。
- 安全与隐私：不记录完整照片、文件内容和密钥；本地预览 Object URL 在替换或卸载时释放；外链暂不进入本子阶段。
- 无障碍：文件选择、风格卡、家具分类按钮、原生 radio 图片选款和弹层可用键盘操作，焦点清晰，选中状态同时用线条和文字表达。
- 图片：22 张三联图覆盖 24 个家具元素，客厅/卧室的主灯和地毯复用图集但选项 ID 独立；每类 3 款共 72 个选项。使用 next/image 本地优化和 CSS 定位显示对应面板；桌面 3 列、小屏 2 列。无远程图片请求。
- 后端边界：本轮不把 `optionId` 伪装成商品 ID，不修改 `POST /tasks`，不声称选图已影响模型输出。后续真实生成接入必须另行实现参数契约与验证。
